# Часть 3. Перегрузка сравнений и демонстрация всех операций {#part3}

Версия v1.0. Класс Polynomial получил перегрузку сравнений `<`, `>`, `<=`, `>=`, `==`, `!=`, а меню —
пункт, показывающий все конструкторы и перегруженные операции. Лабораторная работа выполнена
полностью.

## Что требуется

- Перегрузка бинарных операций сравнения `<`, `>`, `<=`, `>=`, `==`, `!=`.
- Вариант 5: «сравнение значений при определённом x».
- Основной функционал программы должен использовать все перегрузки и конструкторы из пунктов 1–4.

## Как решено

![Диаграмма классов Polynomial, версия v1.0](uml/Polynomial.png)

Многочлены сравниваются по **значениям в общей точке x₀**. Точка хранится в третьем статическом
поле `comparePoint_` (по умолчанию 0) и задаётся статическим методом `setComparePoint()` — в меню
пункт 16. Точка одна на все многочлены, поэтому она статическая: сравнение двух многочленов не
должно зависеть от того, у какого из них «своя» точка.

| Операция | Значение |
|----------|----------|
| `p < q` | P(x₀) < Q(x₀) |
| `p > q` | то же, что `q < p` |
| `p <= q` | то же, что «не `p > q`» |
| `p >= q` | то же, что «не `p < q`» |
| `p == q` | P(x₀) = Q(x₀) с учётом погрешности |
| `p != q` | то же, что «не `p == q`» |

`==` сравнивает значения, а не коэффициенты: разные многочлены бывают «равны» в данной точке.
Например, x² − 3x + 2 и x² при x₀ = 2/3 оба равны 4/9.

Функции сравнения дружественные (`friend`): им нужен доступ к закрытому статическому полю
`comparePoint_`.

## Погрешность и согласованность

Дробные числа хранятся приближённо: 0,1 + 0,2 в компьютере не равно ровно 0,3. Поэтому все
сравнения выражены через одну функцию `compareValues()`, которая считает значения равными, если
они различаются меньше чем на 10⁻¹³ от их величины:

```cpp
int compareValues(double left, double right)   // -1, 0 или 1
{
    const double scale = std::fmax(1.0, std::fmax(std::fabs(left), std::fabs(right)));
    const double difference = left - right;
    if (std::fabs(difference) <= COMPARE_TOLERANCE * scale) { return 0; }
    return difference < 0.0 ? -1 : 1;
}
```

Допуск относительный: для значений порядка 10¹² абсолютная погрешность больше, чем для значений
порядка 1. Первый вариант с допуском 10⁻⁹ тестовая программа забраковала: при x₀ = 10⁶ многочлены
x² и x² + 1 (значения 10¹² и 10¹² + 1) оказались «равными». С допуском 10⁻¹³ они различаются, а
0,1 + 0,2 и 0,3 по-прежнему равны.

Так как `>`, `<=`, `>=`, `!=` выражены через `<` и `==`, а те — через одну функцию, для любых двух
многочленов верно ровно одно из `p < q`, `p == q`, `p > q`, и остальные операции с ними согласованы.

| `+`, `-`, `*`, `/` | 9–10 |
| `<`, `>`, `<=`, `>=`, `==`, `!=` | 17 |
| Статическое поле, корни и счётчик поисков | 6–8, 16 |

Пункт 18 работает со своими многочленами и P, Q не меняет.

В пункте 18 результат каждой операции `++c`, `c++` сначала сохраняется в переменную и только
потом выводится вместе с `c`. Если записать `std::cout << ++c << c` одной строкой, в C++14 порядок
вычисления частей не гарантирован (он определён только с C++17), и `c` могло бы вывестись до
изменения.

## Защита от ошибок

- **Точка сравнения** — только конечное число; иначе исключение `std::invalid_argument`, точка прежняя.
- **Сравнения ничего не меняют** — операнды передаются по константной ссылке.
- **Проверка.** Тестовая программа части 3 — 19 проверок из 19: сравнения в разных точках, равенство
  разных многочленов в одной точке, согласованность всех шести операций в 9 точках, погрешность
  0,1 + 0,2 = 0,3, различие больших значений, отказ для бесконечной точки, неизменность многочленов.
  Проверки частей 1 и 2 — 31 из 31 и 29 из 29.
